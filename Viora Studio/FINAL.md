# VIORA STUDIO 6.0.0: итог работы

Файл для автора. Что сделано, что проверено машиной, что проверить руками
и где границы. Читается за пять минут, дальше по ссылкам.

Поставка: `dist/viora-studio-6.0.0.zip`. Собрана `python3 tools/package.py`,
внутри один скилл и три заглушки-указателя, живых секретов нет.

## Что работает

Телеграм внутри скилла целиком, без бота и без MCP.

1. Вход по QR. `start-watch` рисует QR в консоли и ту же ссылку `tg://login`
   текстом, ждёт сканирования с телефона, пересоздаёт код по истечении, при
   двухфакторке спрашивает пароль облака. Строка сессии ложится в
   `secrets/watch.env` сама. Запасной путь по номеру: `start-watch login phone`.
2. Один процесс в сети. Соединение держит только сторож `tools/tg_watch.py`.
   Он пишет `tg-watch.lock` с pid и сердцебиением, второй экземпляр выходит с
   кодом 3. Все отправки моста (`send`, `stage --send`, `ask --send`, `publish`,
   `ping`) при живом стороже идут через `tg-outbox.jsonl` и получают `msg_id`
   из `tg-outbox-done.jsonl`. Сторож сам отмечает заявку по роли записки.
3. Вложения. Фото и документы до 20 МБ качаются в `media/<msg_id>/`, альбом
   собирается в одну заявку по `grouped_id` за 1.5 секунды, подпись берётся из
   сообщения с текстом. Пути приезжают в поле `media` и в `next --json`.
4. Мозг v2. Порядок ступеней: `tools/agent.py` на подписочном CLI этой машины
   (claude, codex, agy, gemini), потом `tools/ai.py` по ключу, потом каркас без
   модели. `pc`, `weather`, `morning`, `remind` сторож отвечает сам через
   `life.py` и `schedule.py`, мгновенно. Пока думает, пишет «VIORA ВЗЯЛ, ДУМАЮ».
5. Черновик мозга идёт через тот же гейт, что и `stage` у агента в редакторе:
   `lint_post.py --fix`, потом `--strict` с рубрикой. Забраковал: второй заход
   агента с претензиями линтера. Не чисто и после него: автору `VIORA КАРКАС`,
   заявка достаётся агенту в редакторе через `next` под тем же id.
6. Слова автора к черновику мозга отрабатывает сам сторож: «пуб» публикует из
   `drafts/` знак в знак, «правь ...» переписывает, «отложи 20:30» откладывает,
   «стоп» отменяет. К черновикам агента из редактора сторож не прикасается.
7. Расписание внутри сторожа: раз в 60 секунд `schedule.py due`, выполнение,
   `mark`. После сна компьютера пропущенное догоняется один раз, если прошло
   меньше 3 часов.
8. Автозапуск: `tools/autostart.py install|remove|status`. Windows через
   `schtasks /SC ONLOGON` и `pythonw` без окна, macOS через LaunchAgent с
   KeepAlive, Linux через systemd --user. Из запускателя: `start-watch autostart`.
9. Устойчивость: реконнект с паузой от 5 до 300 секунд, лог `watch.log` с
   ротацией на 1 МБ, `doctor` показывает сторожа, outbox, media, агента, автозапуск.

Ревизия части A (5.6.0) и что в ней починено: раздел «Исправлено после части A»
в `viora-studio/CHANGELOG.md`. Главное: своё сообщение узнавалось по первым пяти
буквам без регистра, поэтому «viora реши» терялось; миграция префиксов
дописывала «виора» при каждом чтении; `schedule.py` не понимал живую речь;
правило ноль проверялось только внутри `viora-studio/`; правила Cursor отставали
от правил Antigravity.

## Что проверено машиной

`bash tools/check_all.sh` заканчивается строкой `ВСЁ ЧИСТО`. В прогоне:

| что | проверок |
| --- | --- |
| мост `tg.py` | 125 |
| сторож `tg_watch.py` с фейковым клиентом Телеграма | 99 |
| агент `agent.py` с подменённым subprocess | 54 |
| автозапуск `autostart.py` | 19 |
| расписание `schedule.py` | 93 |
| повседневное `life.py` | 70 |
| нейронка `ai.py` и цепочка `post.py` | 33 и 45 |
| линтер поста, автоправка, оценка, статья | 18, 23, 14, 26 |
| точка входа `viora.py`, размеры, эталоны поведения | 84, 26, 32 |
| сборщик поставки `package.py` | 42 |
| правило ноль по всей поставке | `validate_skill.py --dashes-only ..` |

Что именно покрыто тестами сторожа и моста: разбор команд с префиксом и без
слеша, своё сообщение против обращения автора, ответ реплаем на свой вопрос,
outbox с подтверждением и авто-отметкой заявки, lock и второй экземпляр,
скачивание фото и сборка альбома, пропуск документа больше 20 МБ, все три ступени
мозга и падение с одной на другую, гейт линтера с двумя заходами, «пуб», «правь»,
«отложи», «стоп» к своему черновику и невмешательство в чужой, догон расписания
после сна, ротация лога, отправка с битым `reply_to`, обрезка под лимит Телеграма.

Что покрыто тестами агента: каждый из четырёх CLI (argv и разбор ответа),
пустой вывод, таймаут, ошибка входа, отсутствие всех CLI, повтор через pty у agy,
картинки у codex до разделителя, правка файлов только по слову и `trust=edit`,
запрет на `secrets/` в промпте, чистка ответа от тире и markdown-заголовков.

Прогон с настоящим линтером, без подмен: чистый образец проходит гейт без
изменений, слоп-пост забраковывается 22 претензиями, пост без хэштега чинится
`--fix`. Прогон с подставным `claude` в PATH, который возвращает JSON: `agent.py`
и сторож собирают карточку `VIORA ЧЕРНОВИК` с угаданной рубрикой, тело совпадает
с образцом знак в знак.

Чего машина не проверяла: живого соединения с Телеграмом и живого ответа CLI.
В среде сборки нет ни аккаунта, ни залогиненного агента. Это ровно то, что
проверяет ручной список ниже.

## Проверка руками за пять минут

Тот же список лежит в `TELEGRAM-SETUP.md`, здесь коротко.

1. `start-watch`, QR с телефона. Консоль: «вошёл как ...», «Смена началась».
2. В Избранное `виора как дела`. Реплай в ту же секунду: `VIORA НА СМЕНЕ`.
3. Фото задачи с подписью `виора реши`. Сначала `VIORA ВЗЯЛ, ДУМАЮ`, потом
   `VIORA РЕШЕНИЕ` по картинке. Нет ни одного CLI и ключа: `VIORA БЕЗ МОДЕЛИ`
   с подсказкой, что поставить.
4. `виора место`, `виора погода`. Два ответа без модели.
5. `виора напоминай 08:00 утро`. `VIORA НАПОМИНАНИЕ` со списком,
   с компа `python3 tools/schedule.py list`.
6. `виора пост про ...`. `VIORA ВЗЯЛ, ДУМАЮ`, потом карточка `VIORA ЧЕРНОВИК r1`
   с рубрикой и числом знаков. `виора правь короче`: новая карточка.
   `виора пуб`: `VIORA ГОТОВО r1` со ссылкой на пост в канале.
7. Второй терминал, `python3 tools/tg.py doctor`: «сторож жив, pid ...»,
   «outbox пуст». `python3 tools/tg.py ping`: сообщение уходит через сторожа,
   вторая сессия не открывается.
8. `start-watch autostart`, перезагрузка, снова `виора как дела` без запуска руками.
9. Открой папку в Codex, Antigravity, Claude Code, спроси «что в памяти канала».
   Один и тот же файл `viora-studio/memory/post-log.md`.

Если что-то пошло не так: таблица «Строка в консоли, что делать» в
`TELEGRAM-SETUP.md` и `watch.log` в рабочей папке, путь печатает `doctor`.

## Известные границы

- Компьютер должен быть включён. Сторож это процесс на твоей машине, спящий
  ноутбук не отвечает. После сна догоняются напоминания за последние 3 часа,
  сообщения в Избранном ждут в Телеграме и берутся при подключении.
- Флаги безголовых режимов CLI могут уехать с обновлением самих CLI. Все они
  живут в одном месте: `viora-studio/tools/agent.py`, блок с комментарием «Здесь
  и только здесь живут флаги безголовых режимов» и функция `build_argv` под ним.
  Разбор ответов там же, `parse_output`. Проверено 2026-09-07: claude 2.1.x
  `-p --output-format json --allowedTools`, codex `exec -C --sandbox read-only`
  с `-i` до `--` и промптом после, agy `-p --output-format json`, gemini
  `-p --output-format json`. Если агент перестал отвечать: `python3 tools/agent.py
  run --text "скажи готов" --json` покажет код и хвост stderr.
- agy без TTY иногда молчит (upstream issue #76). На маке и Linux сторож
  повторяет запуск через pty, на Windows такого повтора нет: ставь другой CLI
  или жди фикса в самом agy.
- Качество поста зависит от модели за CLI. Линтер отсекает механику и слоп,
  оценка и смысл остаются на модели и на тебе. Черновик мозга это черновик.
- `ai.py` с локальной моделью (ollama, lmstudio) считается мозгом только при
  живом порте. Не запущен процесс: сторож честно скажет «модели нет».
- Один аккаунт, одно Избранное, один канал из настроек моста. Второй канал
  это второй конфиг: `python3 tools/tg.py config --set channel=@другой`.
- Автозапуск на Linux требует `systemctl --user`. Без него запускатель скажет
  об этом и предложит cron `@reboot` или запуск руками.
- В поставке пустые `secrets/*.env` с API id и hash приложения. Строку сессии
  и ключи моделей `package.py` в архив не пропустит: собирай из чистой копии
  или очищай значения перед сборкой.

## Что не трогалось

Правила поста и футера, пайплайн из одиннадцати шагов, линтеры, оценка,
эталоны поведения, память канала, второй бренд. Всё это осталось как в 5.6.0,
тесты на это проходят без изменений.
