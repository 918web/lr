# Что это за папка

Рабочая папка бренда VIORA STUDIO. Внутри один переносный скилл, который заставляет
любую модель писать посты голосом автора, держит смену в Телеграме, отвечает
на бытовые вопросы с телефона и помнит автора одинаково в Codex, Antigravity,
Cursor и Claude Code. Рядом архив реальных постов как эталон.

Главный принцип: скрипты держат правила, модель держит вкус. Механику текста считает
линтер, цифры про комп и погоду считает код, а от модели нужны только смысл и голос.

Версия: смотри `viora-studio/VERSION`. Что менялось: `viora-studio/CHANGELOG.md`.
Телеграм за три шага: `TELEGRAM-SETUP.md`.

## Один скилл, а не четыре копии

Скилл лежит один раз, в `viora-studio/`. В папках обнаружения `.claude/skills`,
`.agents/skills` и `.cursor/skills` стоит заглушка: `SKILL.md` с той же шапкой
и одной мыслью в теле: настоящий скилл в `../../../viora-studio`, работай там.
Среда видит скилл сразу, а память канала, профиль автора и напоминания у всех
агентов одни. Симлинков нет: проводник Windows и 7-Zip их ломают.

Что едет со скиллом и что живёт в рабочей папке машины:

| Где | Что | Зачем так |
|---|---|---|
| `viora-studio/memory/` | профиль автора, напоминания, метрики, журнал постов, приветствия | это настройки и память автора, они переезжают вместе с папкой |
| `secrets/` | ключи api и строка сессии Телеграма | рядом с поставкой, в `.gitignore`, в промпт агента не попадают |
| `~/.local/state/viora-studio/` | ящик заявок, черновики, outbox, lock, `watch.log`, `media/` | мусор рантайма, один на машину, не едет с архивом |

На Windows рабочая папка это `%USERPROFILE%\.local\state\viora-studio`.

## Установка

### Способ 0. Пришёл архив zip

Распаковывай чем угодно: проводник Windows, 7-Zip, `unzip` на Linux и macOS.
Заглушки в папках обнаружения уже на месте, среда видит скилл сразу.

Правь только `viora-studio/`: расходиться больше нечему. Если среда всё же требует
полные копии, раскатать их можно вручную:

```bash
cd viora-studio
python3 tools/install.py --target .. --copy --dry-run
python3 tools/install.py --target .. --copy
```

Обратно к заглушкам: `python3 tools/install.py --target .. --force`.

### Способ 1. Одной командой в свой проект

```bash
cd viora-studio
python3 tools/install.py --target /путь/до/проекта --dry-run
python3 tools/install.py --target /путь/до/проекта
```

Указатель ложится сразу в три места: `.claude/skills/viora-studio`,
`.agents/skills/viora-studio` и `.cursor/skills/viora-studio`.

Флаги: `--copy` полная копия, `--link` симлинк для Linux и macOS,
`--full` со всеми файлами, `--force` перезаписать чужое, `--uninstall` снести
только своё.

`--global` ставит заглушки с абсолютным путём в `~/.claude/skills`,
`~/.agents/skills`, `~/.cursor/skills` и `~/.gemini/config/skills` для Antigravity:
скилл виден из любого проекта, а правится в одном месте.

### Способ 2. Antigravity, Codex CLI, Cursor, Claude Code без установки

Все четыре среды сами читают один из корневых файлов: `AGENTS.md`, `CLAUDE.md`,
`GEMINI.md`, `.cursorrules`. Они уже лежат в папке и ведут в одно место.

1. Положи папку `Viora Studio` в рабочую директорию, которую видит агент.
2. Первым сообщением в новом чате:

   ```
   Читай Viora Studio/AGENTS.md и Viora Studio/viora-studio/SKILL.md.
   Работаем строго по ним, без исключений.
   ```

3. Дальше задачами: `пишем пост, тип - пак абузов, сырьё ниже: ...`

Первый запуск в любой среде начинается с профиля: агент один раз спрашивает город,
часовой пояс, время подъёма и устройство одним сообщением и пишет ответы
в `viora-studio/memory/profile.md`. Второй раз не спросит ни здесь, ни в другой среде.

### Способ 3. Обычный чат без файлов или телефон

- Короткий вариант: `viora-studio/PROMPT-CORE.txt` в первое сообщение или в кастомные инструкции.
- Полный вариант: `viora-studio/PROMPT-FULL.txt`, если модель держит большой контекст.

Оба файла собираются из тех же источников, руками их править не надо:

```bash
cd viora-studio
python3 tools/build_prompt.py
```

## Телеграм

Три шага: `start-watch`, QR с телефона, `autostart`. Подробно и с проверкой за пять
минут: `TELEGRAM-SETUP.md`. Коротко, что получается:

- В Избранное пишешь `виора как дела`, `виора пк`, `виора погода`, `виора утро`,
  `виора напоминай 08:00 утро`. Сторож отвечает сам, без модели, за секунду.
- Кидаешь фото задачи с подписью `виора реши`. Сторож пишет «взял, думаю», зовёт твой
  Claude Code, Codex, Antigravity или Gemini CLI через `tools/agent.py` и отвечает реплаем.
  Ключи для этого не нужны: работает подписка, которая у тебя уже есть.
- Пишешь `виора пост про ...`. Мозг гонит пайплайн скилла, черновик проходит тот же
  линтер, что и у агента в редакторе, и приезжает карточкой `VIORA ЧЕРНОВИК`.
  В канал он уходит только после твоего `виора пуб`; `виора правь короче` переписывает.
- Соединение с Телеграмом держит один процесс. Агент в редакторе отправляет через него,
  а не заводит второе подключение.

## Как ставить задачу

Чем чище сырьё, тем меньше шансов, что модель начнёт фантазировать.

```
Пишем пост, тип - полезные сервисы.
Сырьё:
1. Сервис X - что делает, цифры, ссылка
2. Сервис Y - что делает, цифры, ссылка
Личное: X завёлся со второго раза, на Y убил полчаса.
Скрины: 3 штуки, на втором видно выбор модели.
```

Строка «Личное» важнее, чем кажется: без неё скилл обязан остановиться и спросить,
потому что личная деталь это железное правило, а выдумывать её запрещено.

Скилл не придумывает цифры, сроки и шаги обхода. Один выдуманный лимит в посте
про халяву стоит дороже, чем весь пост.

## Что обновлять руками

- `viora-studio/memory/metrics.md` через сутки после поста: охват, реакции, подписки.
  Это главный файл скилла: метрики бьют правила.
- `viora-studio/memory/post-log.md` и `used-greetings.md` после каждого поста.
- `viora-studio/memory/decisions.md` каждый раз, когда правишь стиль руками.
- `viora-studio/memory/profile.md` один раз, на первом запуске, агент сделает это сам.
  Поле «предпочитаемый агент» решает, кто отвечает из Телеграма: `claude`, `codex`,
  `agy`, `gemini` или `auto`. Если репозиторий публичный, внеси файл в `.gitignore`:
  в нём город и распорядок дня автора.
- `viora-studio/reference/brand.md` новые проекты, релизы, счётчики подписчиков.
- `posts/` и `posts/INDEX.md` новый вышедший пост. Это лучшее топливо для стиля.

Записать метрику можно командой, чтобы не портить формат файла:

```bash
cd viora-studio
python3 tools/memory.py add-metric --views 165 --reactions 4 --comments 1 --note "пак абузов" --dry-run
```

После правок в `reference/` или `SKILL.md`: поднять `VERSION`, дописать `CHANGELOG.md`,
пересобрать промпты и прогнать `bash tools/check_all.sh`.

## Проверить, что всё живое

```bash
cd viora-studio
bash tools/check_all.sh
```

Одна команда гоняет все секции: самопроверки всех скриптов, включая мост, сторожа
с фейковым клиентом, агента с подменённым subprocess и автозапуск, сборку промптов
и сверку с источником, строгую проверку образцового поста, среду, 32 эталона поведения,
установку в чистую папку, состав поставки, упаковку по спеке Agent Skills и поиск
длинных тире по всей поставке. В конце должно быть `ВСЁ ЧИСТО`.

По отдельности:

```bash
python3 tools/lint_post.py черновик.txt --strict
python3 tools/viora.py doctor
python3 tools/tg.py doctor
python3 tools/validate_skill.py
python3 tools/run_evals.py
python3 tools/build_prompt.py --check
python3 tools/sizes.py --check
python3 tools/package.py --check
```

Если правишь сам скилл, порядок такой: правка, `build_prompt.py`, `sizes.py --write`,
`validate_skill.py`, `run_evals.py`, `check_all.sh`. Только после этого поднимается версия
и собирается поставка: `python3 tools/package.py`.

Сборщик по умолчанию делает переносимый архив с заглушками: скилл лежит в нём
один раз, а в трёх папках обнаружения стоит указатель на `viora-studio`. Готовый zip
проверяется тут же: никаких ссылок, никаких путей с "..", имена допустимы в Windows,
скилл внутри ровно один. Заполненная строка сессии или ключ модели в `secrets/*.env`
останавливают сборку: живой доступ к аккаунту в архив не поедет. Старое поведение
с четырьмя полными копиями даёт флаг `--copies`, вариант со ссылками для Linux
и macOS даёт флаг `--links`.
