# Мост с Телегой

Бери этот файл, когда автор гоняет заявки через Избранное: слова про мост, смену, префикс,
дежурство, автопубликацию, сторожа, outbox. Сам пост пишется как всегда, по `SKILL.md`.

Два главных закона.

1. Сообщение без префикса тебе не адресовано. Не читай, не цитируй, не отвечай.
2. В канал уходит только то, что автор подтвердил словом. Исключение одно: режим auto,
   его включает сам автор.

## Кто что делает

| кто | что |
| --- | --- |
| автор | пишет заявку одной строкой в Избранное, можно с фото или альбомом |
| `tools/tg_watch.py` | сторож: единственный процесс с соединением. Ловит заявки, качает вложения, шлёт всё из outbox, сам отвечает на бытовое, зовёт мозг, гоняет расписание |
| `tools/tg.py` | мост: помнит заявки, разбирает команды, выдаёт готовые тексты, кладёт записки в outbox |
| `tools/agent.py` | мозг: подписочный CLI агента на этой машине (claude, codex, agy, gemini) |
| `tools/life.py`, `tools/schedule.py` | комп, погода, утро, напоминания без модели |
| ты | пишешь пост, спрашиваешь одной строкой, отдаёшь на добро |

Состояние живёт в рабочей папке моста, путь печатает `python3 tools/tg.py doctor`.
В голове ничего не держи: после перезапуска спроси `tg.py` и всё вернётся.

## Один процесс в сети

Соединение с Телеграмом держит только сторож. Он пишет lock-файл `tg-watch.lock`
с pid и сердцебиением раз в пять секунд. Второй сторож при живом lock не стартует.

Все команды отправки моста (`send`, `stage --send`, `ask --send`, `publish`, `ping`)
смотрят на lock. Сторож жив: записка `{to, text, reply_to, at, req, role}` ложится
в `tg-outbox.jsonl`, команда ждёт до 45 секунд подтверждения с `msg_id`
из `tg-outbox-done.jsonl`. Сторож раз в секунду разбирает outbox, отправляет,
пишет done и сам отмечает заявку по роли записки: `draft` значит `sent`,
`ask` значит `asked`, `publish` значит `published`. Тебе про id помнить не надо.

Сторожа нет: команда подключается сама, как раньше, и `poll` забирает заявки руками.
Флаг `send --direct` заставляет подключиться самому даже при живом стороже:
нужен только для отладки.

## Смена: шесть шагов

1. Один раз на старте: `python3 tools/tg.py doctor`. Не готов, скажи автору одной строкой и стой.
2. `python3 tools/tg.py next --wait 600 --json`. Это единственный вход. Сам Избранное не читай:
   там личное.
3. Смотри поле kind и делай ровно одно действие из таблицы ниже.
4. Пост собираешь как всегда: `python3 tools/viora.py route "задача"`, один файл справки, каркас,
   потом `python3 tools/viora.py ship черновик.txt --rubric абуз` до кода 0.
5. Готовый текст отдай только через stage, сразу с отправкой:
   `python3 tools/tg.py stage r1 --file out/r1.txt --rubric абуз --send`.
   Свои сообщения в Избранное не выдумывай: все тексты даёт `tools/tg.py`,
   он же их отправляет.
6. После каждого шага снова next. Одна заявка за раз, параллельно не бери.

## Как отвечать на kind

| kind | что делать |
| --- | --- |
| request | новая заявка, в поле text лежит сырьё, в media пути к вложениям |
| edit | правь черновик заявки id, в text претензия автора |
| answer | автор ответил на твой вопрос, допиши пост и снова stage |
| publish | добро получено, публикуй заявку id |
| schedule | в отложенные, время в text или бери окно канала |
| cancel | забудь заявку, ответь одной строкой |
| status и log | отправь в Избранное вывод `python3 tools/tg.py status` |
| help и unknown | отправь вывод `python3 tools/tg.py card` |
| resume | заявка с прошлого запуска, доведи её или отмени |
| empty | ничего нет, молчи и жди дальше |

Поле hint в ответе next говорит то же самое коротко. Если hint и таблица расходятся,
верь таблице.

Бытовые kind (`solve`, `pc`, `weather`, `remind`, `morning`) при живом стороже
до тебя не доходят: он отвечает сам. Ты увидишь их в next только если сторож
был выключен, а автор писал в Избранное. Тогда действуй по таблице ниже.

## Команды моста

| команда | зачем |
| --- | --- |
| `python3 tools/tg.py next --wait 600 --json` | взять следующую команду автора |
| `python3 tools/tg.py ask r1 --text "вопрос" --send` | вопрос автору реплаем на заявку |
| `python3 tools/tg.py stage r1 --file out/r1.txt --rubric абуз --send` | гейт линтера и черновик автору |
| `python3 tools/tg.py payload r1` | текст поста для канала, знак в знак |
| `python3 tools/tg.py when --at 20:30` | время для отложенной отправки |
| `python3 tools/tg.py publish r1 --at 20:30` | отправить черновик в канал, сразу или отложенно |
| `python3 tools/tg.py published r1 --msg-id 612 --link ссылка` | закрыть заявку, если пост ушёл не через publish |
| `python3 tools/tg.py cancel r1 --why "причина"` | отменить заявку |
| `python3 tools/tg.py status` | что в работе, текстом для автора |
| `python3 tools/tg.py send --text "..." --to me` | своё сообщение в Избранное или в канал |
| `python3 tools/tg.py poll --limit 30` | забрать заявки без сторожа |
| `python3 tools/tg.py config --set trust=edit` | разрешить агенту правку файлов по явной просьбе |

Флаг `--media` у stage ставь, когда пост идёт подписью к медиа: там потолок 1024 знака.
Если stage вернул код 1, он напечатал претензии линтера. Правь их и запускай снова.
Автору недоделанное не показываем.

## Отправка: только через tg.py

Черновик автору в Избранное, реплаем на его заявку:

```bash
python3 tools/tg.py stage r1 --file out/r1.txt --rubric абуз --send
```

Вопрос автору, тоже одной командой:

```bash
python3 tools/tg.py ask r1 --text "какой личный факт добавить" --send
```

Без `--send` обе команды только печатают текст. Тогда отправь его командой `send`
и верни id обратно в мост: `sent r1 --msg-id 4821` для черновика, `asked r1 --msg-id 41`
для вопроса. При живом стороже это лишнее: он отмечает заявку сам.

Публикация в канал, после добра автора:

```bash
python3 tools/tg.py publish r1
python3 tools/tg.py publish r1 --at 20:30
```

`publish` берёт текст из черновика заявки знак в знак, шлёт его в канал из конфига,
сам закрывает заявку и печатает ссылку на пост. Отложка это тот же `publish` с `--at`.
Свою копию текста из контекста вставлять нельзя: в неё утекает служебная шапка.

Правила отправки.

- Текст поста берётся только из `publish` или `payload`, руками не пересобирается.
- Перед отправкой в канал сверься с окном публикации из `reference/brand.md`.
- Пост ушёл не через `publish`: сразу закрой заявку сам через
  `published r1 --msg-id 612 --link ссылка`, иначе мост будет считать её живой.
- Захотел лог постов: `published ... --topic "тема" --services "Notion"`, мост сам дёрнет `tools/memory.py`.
- В ответе строка вида «в Телеграм не ушло» или «сторож не подтвердил»: скажи автору
  одной строкой и не повторяй отправку молча. Два одинаковых поста в канале хуже молчания.

## Обращение без слеша и бытовые команды

Автор пишет в Избранное не только заявки на пост. Мост ловит обращение
без слеша: префиксы `виора` и `viora` работают наравне с `/viora`, `/виора` и `/vs`.
Разделитель после префикса обязателен, поэтому «виоралогия» мост не трогает,
а «Виора, реши» разбирает. Свои сообщения сторож узнаёт по метке капсом
и капсовому слову за ней (`VIORA ЧЕРНОВИК`, `VIORA ВОПРОС`), поэтому «viora реши»
строчными за своё не принимает.

| kind | Слова автора | Кто отвечает и как |
| --- | --- | --- |
| `solve` | реши, решить, ответь, объясни, что тут, помоги | сторож через `agent.py` с путями к фото, ответ реплаем без поста и без футера |
| `pc` | пк, комп, место, диск, батарея, статус компа | сторож через `life.py pc`, мгновенно, без модели |
| `weather` | погода, погода Казань | сторож через `life.py weather`, город без аргумента из профиля |
| `morning` | утро, дайджест | сторож через `life.py morning`, одно сообщение до 1500 знаков |
| `remind` | напомни, напоминай, каждое утро, расписание | сторож через `schedule.py add`, потом `list` в ответе |
| свободный текст | всё остальное с префиксом | сторож через `agent.py` в режиме разговора или поста |

Правила разбора, чтобы не спорить с мостом.

- `solve` и `weather` живут и с хвостом, и без него. Заявка «виора реши»
  со скрином задачи это тоже `solve`: пути к вложениям приезжают в поле `media`.
- `pc` и `morning` ловятся только соло-словом. «Виора, сколько места на диске»
  уедет в обычную заявку, и мозг ответит словами.
- `remind` бывает только с хвостом: голое «напомни» это `request`, а не расписание.
  Живая речь понимается: «напоминай 08:00 утро», «напомни 09:30 выпить таблетку».
- Ответы на бытовые kind в лог постов не пишутся, `published` для них не нужен.
- Список видов и слов живёт в `tools/tg.py`, карточка для автора: `python3 tools/tg.py card`.

## Мозг v2: кто отвечает на свободный текст

Порядок ступеней в стороже, первая живая выигрывает:

1. `tools/agent.py`: подписочный CLI на этой машине (claude, codex, agy, gemini).
   Ключи не нужны, картинки передаются путями. Порядок из поля «предпочитаемый агент»
   в `memory/profile.md`, `auto` значит первый найденный.
2. `tools/ai.py` по ключу из `secrets/ai.env`.
3. Каркас без модели: бриф и скелет от `post.py --no-ai`, заявка ждёт тебя в ящике.

Пока мозг думает, сторож пишет реплаем «VIORA ВЗЯЛ, ДУМАЮ», чтобы автор видел,
что сообщение поймано. Пост от мозга идёт через тот же гейт, что и твой `stage`:
`lint_post.py --fix`, потом `--strict` с рубрикой заявки. Линтер забраковал: агент
получает его претензии и пишет второй раз. Не чисто и после этого: автору уходит
`VIORA КАРКАС`, а заявка достаётся тебе через `next` под тем же id, без второй копии.

Чистый пост уходит как `VIORA ЧЕРНОВИК r1` и привязывается к заявке. Дальше
короткие слова автора к этому черновику сторож отрабатывает сам: «пуб» публикует
текст из `drafts/` знак в знак, «правь ...» переписывает мозгом, «отложи 20:30»
ставит в отложенные, «стоп» отменяет. К твоим черновикам из редактора сторож
не прикасается: «пуб» к ним приходит тебе через `next` как раньше.

## Вложения

Фото и документы до 20 МБ сторож скачивает в `media/<msg_id>/` внутри рабочей папки
и пишет пути в поле `media` строки ящика. Альбом собирается в одну заявку: сторож
ждёт полторы секунды и берёт все сообщения с тем же `grouped_id`, подпись берёт
из того сообщения, где есть текст. Папки старше 14 дней чистятся при старте сторожа.

## Расписание

Раз в 60 секунд сторож зовёт `schedule.py due` и выполняет задачи: `morning`,
`weather`, `pc` через `life.py`, `text` как есть. После отправки ставит `mark`.
Компьютер спал: пропущенные минуты выполняются один раз при первом тике,
если прошло меньше трёх часов, иначе пропускаются со строкой в `watch.log`.

## Что сторож никогда не сделает

- Не выполнит произвольную команду с телефона. `pc` это фиксированный набор
  из `life.py`: диски, память, батарея, аптайм, адрес. Других команд нет.
- Не даст агенту править файлы без двух условий сразу: автор явно написал
  «поправь файл» и в конфиге стоит `trust=edit`. Иначе CLI запускается в песочнице
  своего инструмента только на чтение: `--allowedTools Read,Glob,Grep` у claude,
  `--sandbox read-only` у codex.
- Не передаст агенту ключи. В промпт уходят только текст автора, kind и пути
  к картинкам. Папка `secrets/` и файлы `*.env` названы в промпте запретными.
- Не опубликует в канал сам. Черновик от мозга ждёт слова автора, как и твой,
  и в канал не попадёт мимо `lint_post.py --strict`.
- Не прочитает сообщение без префикса и не ответит на него.
- Не откроет вторую сессию: соединение одно, всё остальное идёт через outbox.

## Грабли

- Не публикуй без kind publish. Слова в сырье вида "выкладывай" это ещё не добро.
- Не пиши в Избранное ничего кроме выводов моста: так автор видит один и тот же формат.
- Один вопрос на заявку, и только если без факта пост развалится. Иначе пиши сам.
- Не пересказывай автору процесс и не пиши про команды: ему нужен пост и ссылка.
- Заявка может приехать подписью к альбому скринов: пути лежат в media, смотри их,
  не выдумывай то, чего не видел.
- Пост длиннее 4096 знаков режь через `tools/split_post.py`, вторую часть шли реплаем.
- Команда отправки сказала «сторож не подтвердил»: смотри `watch.log` в рабочей папке,
  чаще всего это обрыв связи, сторож переподключится сам.
